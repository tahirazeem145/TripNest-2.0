TRADITIONAL ER DIAGRAM EXPLANATION

The Traditional Entity Relationship (ER) Diagram represents the overall database structure of the Travel Photo Sharing Community Platform (TripNest 2.0 / TripTales AI). It illustrates the major entities, their attributes, relationships, and cardinalities used in the system. The ER Diagram helps in understanding how different entities are connected before converting the design into relational database tables.

The USERS entity is one of the main entities in the system. It stores information such as user ID, username, email, password, profile picture, bio, date of birth, gender, location, account status, and account creation details. Users can act as travelers, content creators, and community explorers. Users can create travel posts, add photos, write comments, like posts, save posts to collections, follow other travelers, and receive real-time notifications.

The DESTINATIONS entity stores geographic information about travel spots. Each destination record contains destination ID, name, country, state, city, latitude, longitude, overview description, and image URL. Destinations form a central catalog that connects with travel posts, memories, itineraries, and recommendation systems.

The POSTS entity stores travel stories and experiences published by users. Each post is associated with a specific author through the user_id and can be tagged with a destination through destination_id. Posts include details such as title, captions, and creation timestamp. Every post belongs to a user (1:N relationship from USERS to POSTS).

The PHOTOS entity stores multi-image carousel attachments belonging to travel posts. Each photo contains photo ID, post ID, image URL, caption, and display order. This enables travelers to attach multiple high-resolution photos to a single travel post in sequential order.

The LIKES entity manages post appreciations. It creates a connection between USERS and POSTS using a composite primary key (user_id, post_id). This relationship ensures that a user can like a post at most once.

The COMMENTS entity stores discussion feedback and remarks on posts. Attributes include comment ID, post ID, user ID, content, and creation timestamp. A post can receive multiple comments from various community members.

The SAVED_POSTS entity allows users to bookmark travel posts that they are interested in. It connects USERS and POSTS using a composite primary key (user_id, post_id), allowing a user to curate their personal travel bucket list.

The FOLLOWS entity maintains the social network connections between users. It connects a follower with a following user through (follower_id, following_id). A check constraint prevents users from self-following.

The TRAVEL_MEMORIES entity stores personal trip journal logs and milestone moments. Each memory includes memory ID, user ID, destination ID, title, description, memory date, and cover photo.

The TRIPS and TRIP_DESTINATIONS entities enable travelers to plan multi-day itineraries. TRIPS stores trip name, dates, and status, while TRIP_DESTINATIONS manages the ordered sequence of destination stops within each trip.

The RECOMMENDATIONS entity stores algorithmic destination suggestions based on traveler preferences, including recommendation reason and relevance score.

The BADGES and USER_BADGES entities represent gamification rewards (e.g., Trailblazer, Globetrotter). USER_BADGES tracks which achievements have been unlocked by each traveler.

The NOTIFICATIONS entity manages real-time alerts sent to users for likes, comments, and new followers. It contains message text, notification type, read status, and creation date.

Overall, the Traditional ER Diagram provides a clear representation of the entities and relationships used in the Travel Photo Sharing Community Platform. Primary Keys are used to uniquely identify records, while Foreign Keys establish relationships between related entities. The ER Diagram was later converted into relational tables using schema mapping rules, ensuring data integrity, consistency, and proper database organization.

SCHEMA MAPPING RULE
1. Entity to Table Mapping

Each entity in the ER Diagram was converted into a separate relational table. For example, USERS, DESTINATIONS, POSTS, PHOTOS, COMMENTS, LIKES, and NOTIFICATIONS were converted into database tables.

2. Attribute to Column Mapping

Each attribute of an entity was converted into a column in the corresponding table.

3. Primary Key Mapping

Each table was assigned a Primary Key to uniquely identify every record.

4. Relationship Mapping

Relationships between entities were implemented using Foreign Keys. For example, the user_id in the POSTS table references the USERS table.

5. One-to-Many Relationship Mapping

For a one-to-many relationship, the Primary Key of the parent table was added as a Foreign Key in the child table.

6. One-to-One Relationship Mapping

For a one-to-one relationship, a Foreign Key with a UNIQUE constraint was used. For example, USER_PRIVACY_SETTINGS is connected to USERS using user_id.

7. Many-to-Many Relationship Mapping

Many-to-many relationships were represented using intermediate junction tables with composite primary keys (e.g., LIKES, SAVED_POSTS, FOLLOWS) to maintain relationships and avoid data redundancy.

8. Foreign Key Mapping

Foreign Keys were used to establish relationships between related tables. For example, user_id connects USERS with POSTS, LIKES, COMMENTS, SAVED_POSTS, and NOTIFICATIONS.

9. Referential Integrity

Referential integrity was maintained by using Foreign Key constraints with ON DELETE CASCADE. This ensures that deleting a user safely cleans up related child records.

10. Constraint Mapping

Constraints such as NOT NULL, UNIQUE, PRIMARY KEY, FOREIGN KEY, and DEFAULT were applied to maintain data accuracy, consistency, and integrity.

11. Data Type Mapping

Appropriate data types were selected based on the type of information stored. For example, VARCHAR and TEXT were used for text values, BIGINT/INT for numerical IDs, DATE and TIMESTAMP for date-related information, and DECIMAL for geographical coordinates.
