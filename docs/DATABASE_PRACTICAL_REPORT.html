1. Objective (In Simple English)

The purpose of this practical project is to design, implement, and test the database for a Travel Photo Sharing Community Platform (TripNest 2.0):

  • Create Tables: Build tables to store users, travel posts, destination places, photos, likes, and comments.
  • Connect Tables: Link them using Primary Keys (unique IDs) and Foreign Keys with ON DELETE CASCADE (so deleting a user safely cleans up their posts).
  • Insert Sample Data: Add clean, realistic travel records.
  • Test SQL JOINs: Learn how to pull data from two tables together using INNER, LEFT, RIGHT, FULL, and NATURAL joins.
  • Test Safety Errors: Try making mistakes on purpose (like liking a post twice) to verify that the database protects data integrity.

3. Table Creation & Safety Rules (DDL)

The database uses standard SQL rules to keep data clean and organized:

Key Concepts Used:
• PRIMARY KEY: Unique ID for every row.
• FOREIGN KEY ... ON DELETE CASCADE: If a user deletes their account, all their posts and likes are automatically cleaned up.
• CHECK (follower_id <> following_id): Prevents users from following themselves.

5. JOIN Operations Explained with Simple Examples

A JOIN simply means: "Combine information from Table A with related information from Table B."

5.1 INNER JOIN (Matching Rows Only)

In plain English: "Show me only the users who have created a post, along with their post title." (Users with 0 posts are left out).

mysql> SELECT u.username, p.title FROM users u INNER JOIN posts p ON u.user_id = p.user_id; +--------------+------------------------------+ | username | title | +--------------+------------------------------+ | traveluser01 | Beautiful Ooty Trip | | traveluser01 | Another Munnar Experience | | traveluser02 | Exploring Goa | | traveluser03 | Munnar Tea Gardens | | traveluser04 | Jaipur Heritage Tour | | traveluser05 | Mountain Adventure in Manali | +--------------+------------------------------+ 6 rows in set (0.00 sec)

5.2 LEFT JOIN (All Left Users + Matching Posts)

In plain English: "Show me ALL users from the left table, even if they have created 0 posts." (If a user has 0 posts, title shows NULL).

mysql> SELECT u.username, p.title FROM users u LEFT JOIN posts p ON u.user_id = p.user_id; +--------------+------------------------------+ | username | title | +--------------+------------------------------+ | traveluser01 | Beautiful Ooty Trip | | traveluser01 | Another Munnar Experience | | traveluser02 | Exploring Goa | | traveluser03 | Munnar Tea Gardens | | traveluser04 | Jaipur Heritage Tour | | traveluser05 | Mountain Adventure in Manali | +--------------+------------------------------+ 6 rows in set (0.00 sec)

5.3 RIGHT JOIN (All Right Destinations + Matching Posts)

In plain English: "Show me ALL destinations, even if no post is tagged there yet."

mysql> SELECT d.name AS destination, p.title FROM posts p RIGHT JOIN destinations d ON p.destination_id = d.destination_id; +-------------+------------------------------+ | destination | title | +-------------+------------------------------+ | Ooty | Beautiful Ooty Trip | | Goa | Exploring Goa | | Munnar | Munnar Tea Gardens | | Munnar | Another Munnar Experience | | Jaipur | Jaipur Heritage Tour | | Manali | Mountain Adventure in Manali | +-------------+------------------------------+ 6 rows in set (0.00 sec)

5.4 FULL JOIN (FULL OUTER JOIN)

In plain English: "Show me EVERYTHING from both tables. If a row has no match, show NULL."

mysql> SELECT u.username, p.title FROM users u LEFT JOIN posts p ON u.user_id = p.user_id -> UNION -> SELECT u.username, p.title FROM users u RIGHT JOIN posts p ON u.user_id = p.user_id; +--------------+------------------------------+ | username | title | +--------------+------------------------------+ | traveluser01 | Beautiful Ooty Trip | | traveluser01 | Another Munnar Experience | | traveluser02 | Exploring Goa | | traveluser03 | Munnar Tea Gardens | | traveluser04 | Jaipur Heritage Tour | | traveluser05 | Mountain Adventure in Manali | +--------------+------------------------------+ 6 rows in set (0.03 sec)

5.5 NATURAL JOIN

In plain English: "Let the database automatically find columns with the same name in both tables and join them."

mysql> SELECT user_id, username, post_id, title FROM users NATURAL JOIN posts; Empty set (0.05 sec)

(Why Empty set? Because both tables also have a created_at timestamp which differ by seconds, so zero rows match. In real projects, we always use explicit INNER JOIN ... ON).

6. Composite Keys & Safety Error Testing

What is a Composite Key?
It means combining two columns together (like user_id + post_id) to make the unique ID. This stops a user from liking the same post multiple times by accident!

6.1 Test 1: Trying to like the same post twice (ERROR 1062)

mysql> INSERT INTO likes (user_id, post_id) VALUES (2, 1); ERROR 1062 (23000): Duplicate entry '2-1' for key 'likes.PRIMARY'

Why this is good: The Composite Primary Key stopped the duplicate like automatically!

6.2 Test 2: Trying to create a post for a fake user (ERROR 1452)

mysql> INSERT INTO posts (user_id, destination_id, title) VALUES (999, 1, 'Ghost Post'); ERROR 1452 (23000): Cannot add or update a child row: a foreign key constraint fails (`tripnest_db`.`posts`, CONSTRAINT `fk_post_user` FOREIGN KEY (`user_id`) REFERENCES `users` (`user_id`) ON DELETE CASCADE)

Why this is good: The Foreign Key stopped an orphan post from entering the database.

6.3 Test 3: Trying to follow yourself (ERROR 3819)

mysql> INSERT INTO follows (follower_id, following_id) VALUES (1, 1); ERROR 3819 (HY000): Check constraint 'chk_not_self_follow' is violated.

Why this is good: The Check Constraint stopped a user from following themselves.
