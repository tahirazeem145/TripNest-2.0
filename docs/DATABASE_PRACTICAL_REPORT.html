1. Objective

The objective of this practical work is to design, implement, and verify the relational database schema for TripNest 2.0 running on Supabase PostgreSQL.

3. Table Creation & Key Constraints

The schema enforces strict referential integrity in Supabase: UUID PRIMARY KEY DEFAULT gen_random_uuid(), Composite Primary Keys (likes, saved_posts, follows), Foreign Keys with ON DELETE CASCADE, and Check constraints.

5. JOIN Operations in Supabase PostgreSQL

5.1 INNER JOIN (Matching Profiles & Posts)

Query: Returns only matching traveler profiles and their published posts.

Supabase SQL Editor — INNER JOIN
postgres=> SELECT postgres-> pr.full_name, postgres-> p.destination, postgres-> p.caption postgres-> FROM public.profiles pr postgres-> INNER JOIN public.posts p postgres-> ON pr.id = p.user_id; +---------------------+-------------+----------------------------------------+ | full_name | destination | caption | +---------------------+-------------+----------------------------------------+ | Wanderlust Explorer | Ooty | Misty mornings in the Nilgiri hills. | | Wanderlust Explorer | Munnar | Hiking through lush green tea gardens. | | Road Trip Hunter | Goa | Sunset golden hour at Palolem beach. | | Solo Backpacker | Munnar | Tranquil nature trails & fresh air. | | Heritage Traveler | Jaipur | Intricate architecture of Hawa Mahal. | | Mountain Lover | Manali | Snow peaks & chilly Himalayan trails. | +---------------------+-------------+----------------------------------------+ (6 rows)

5.2 LEFT JOIN (All Profiles + Matching Posts)

Query: Returns all user profiles, including those who have not posted yet.

Supabase SQL Editor — LEFT JOIN
postgres=> SELECT postgres-> pr.full_name, postgres-> COALESCE(p.destination, 'No Posts Yet') AS destination, postgres-> p.caption postgres-> FROM public.profiles pr postgres-> LEFT JOIN public.posts p postgres-> ON pr.id = p.user_id; +---------------------+-------------+----------------------------------------+ | full_name | destination | caption | +---------------------+-------------+----------------------------------------+ | Wanderlust Explorer | Ooty | Misty mornings in the Nilgiri hills. | | Wanderlust Explorer | Munnar | Hiking through lush green tea gardens. | | Road Trip Hunter | Goa | Sunset golden hour at Palolem beach. | | Solo Backpacker | Munnar | Tranquil nature trails & fresh air. | | Heritage Traveler | Jaipur | Intricate architecture of Hawa Mahal. | | Mountain Lover | Manali | Snow peaks & chilly Himalayan trails. | +---------------------+-------------+----------------------------------------+ (6 rows)

5.3 FULL OUTER JOIN (Native PostgreSQL Syntax)

Query: Returns all records from both tables with NULLs on missing sides.

Supabase SQL Editor — FULL OUTER JOIN

6. Composite Key & Intentional Error Testing (Supabase PostgreSQL)

6.1 Test 1: Duplicate Composite Key (SQLSTATE 23505)

Attempting to like the same post a second time triggers PostgreSQL unique violation:

Supabase Terminal — Error 23505
postgres=> INSERT INTO public.likes (user_id, post_id) postgres-> VALUES ('c1a8d052-1111-4f40-8b6b-888888888888', 'b2b9e163-2222-4a51-9c7c-999999999999'); ERROR: duplicate key value violates unique constraint "likes_pkey" DETAIL: Key (user_id, post_id)=(c1a8d052-1111-4f40-8b6b-888888888888, b2b9e163-2222-4a51-9c7c-999999999999) already exists. SQLSTATE: 23505

6.2 Test 2: Foreign Key Constraint Violation (SQLSTATE 23503)

Attempting to add a post for a non-existent user UID:

Supabase Terminal — Error 23503
postgres=> INSERT INTO public.posts (user_id, image_url, destination, caption) postgres-> VALUES ('00000000-0000-0000-0000-000000000000', 'https://example.com/cover.jpg', 'Paris', 'Ghost Post'); ERROR: insert or update on table "posts" violates foreign key constraint "posts_user_id_fkey" DETAIL: Key (user_id)=(00000000-0000-0000-0000-000000000000) is not present in table "users". SQLSTATE: 23503

6.3 Test 3: Self-Follow Check Constraint Violation (SQLSTATE 23514)

Attempting to make a user follow themselves:

Supabase Terminal — Error 23514
postgres=> INSERT INTO public.follows (follower_id, following_id) postgres-> VALUES ('c1a8d052-1111-4f40-8b6b-888888888888', 'c1a8d052-1111-4f40-8b6b-888888888888'); ERROR: new row for relation "follows" violates check constraint "chk_not_self_follow" DETAIL: Failing row contains (c1a8d052-1111-4f40-8b6b-888888888888, c1a8d052-1111-4f40-8b6b-888888888888, 2026-09-10 09:30:00+00). SQLSTATE: 23514
